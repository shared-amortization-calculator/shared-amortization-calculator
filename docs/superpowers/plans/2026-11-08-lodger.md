# Lodger Rent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional lodger whose fixed monthly rent covers part of the regular mortgage payment for a set number of months. The monthly payment split then applies to the remainder.

**Architecture:** The engine (`computeSchedule`) takes an effective rent and month count. Each month it takes the rent off the regular payment before splitting what's left by `paymentShare`, and it reports per-row and total lodger figures. The loan schedule itself is untouched. App state gains three lodger fields that travel in the URL. The UI adds a Lodger box in People, two-period amounts in the payment split, a headline figure, a Lodger entry in the repaid summary, and shading plus a table column on the two over-time charts. The word is "roommate" for USD and "lodger" otherwise.

**Tech Stack:** React 19 + TypeScript, Recharts 3, Vitest, Playwright + axe-core.

**Spec:** `docs/superpowers/specs/2026-11-08-lodger-design.md`

## Global Constraints

- When the lodger box is unticked, every figure, chart, table and label must be identical to today's.
- The loan schedule (`buildLoanSchedule`), balance, interest, payoff month and overpayments are never changed by the lodger.
- People's equity must sum to total equity in all four equity rules.
- The lodger word comes from `lodgerTerm(currency)`: `'roommate'` for USD, `'lodger'` for GBP, EUR and AUD. Code identifiers and URL parameters stay `lodger…`.
- Defaults: `lodgerEnabled: false`, `lodgerRentMonthly: 500`, `lodgerMonths: 60`.
- URL parameters: `lodger` (`1`/`0`), `lrent`, `lmonths`, always written.
- WCAG 2.2 AAA: axe passes with the lodger on. Text drawn on charts uses `TEXT_COLOR`. The tick box's label is a target at least 44px tall, like `.pin-results`.
- Follow existing patterns: `NumberField`, `SliderField`, `EndStats`, `DataTable`, `readNumber`.
- Unit tests: `npm test`. End-to-end: `npx playwright test`. Build and type check: `npm run build`.

## Review Focus

1. **Three people plus a lodger in the repaid summary.** The Lodger entry is the fourth `EndStats` item, and `PERSON_COLORS[3]` is undefined. It must get its own border colour (Task 5 test).
2. **Rent that covers the whole payment.** The remainder is £0, so the amount boxes show £0 and typing does nothing. The "then" amounts still show and nothing reads NaN (Task 4 test).
3. **Rent lasting longer than the loan** (months ≥ payoff, including after overpayments). The split shows "while the lodger pays" with no "then" part, and the headline says "whole loan" (Task 3 and Task 4 tests).
4. **Box ticked with rent £0.** This behaves exactly like unticked: no headline figure, no Lodger entry, no shading or column, and today's split text (Task 3 and Task 5 tests).
5. **A shared link carrying only lodger parameters**, such as `?lodger=1&lrent=700`. It must open with the lodger on rather than being ignored (Task 3 test).

### Task 4: Lodger box and the two-period payment split

**Files:**
- Create: `src/components/LodgerControls.tsx`
- Modify: `src/components/SplitControl.tsx`, `src/components/PeopleControls/PeopleControls.tsx`, `src/App.tsx`, `src/styles.css`
- Test: `tests/lodger.spec.ts` (new)

**Interfaces:**
- Consumes: Task 2's `lodgerTerm` and `formatMonthCount`. Task 3's `AppState` fields, `lodgerActive`, `paymentAfterLodger`, `lodgerCoversLoan` and `lodgerPeriod`.
- Produces:
  - `SplitControl` gains an optional prop `periods?: { during: string; afterTotal: number | null }`.
  - `PeopleControls` takes `result: ScheduleResult` in place of `monthlyPayment: number`. `App.tsx` passes `result`.

Behaviour of `periods`. It applies only when there is more than one person, and when `periods` is undefined the output is exactly today's.

- **People before the last:** after the amount box, add `<span className="split-period">` containing `during`. When `afterTotal` is not null, append `` ` · then ${money(share * afterTotal)}` ``.
- **The last person:** the line becomes `{name} share: {pct} ({amount} {during}, then {money(share * afterTotal)}, the remainder)`. When `afterTotal` is null, it is `({amount} {during}, the remainder)`.

`PeopleControls` passes the following when `lodgerActive(state)`:

- `total = paymentAfterLodger(result.monthlyPayment, state)`
- `periods = { during: lodgerCoversLoan(result) ? `while the ${term} pays` : lodgerPeriod(result), afterTotal: lodgerCoversLoan(result) ? null : result.monthlyPayment }`

Otherwise it passes `total = result.monthlyPayment` and no `periods`.

`LodgerControls({ state, update })` renders:

- `<fieldset>` with legend `capitalize(term)`.
- A tick box labelled `` `We have a ${term}` ``, in a label styled like `.pin-results`.
- When ticked, `NumberField` "Rent per month", with min 0 and the currency prefix.
- When ticked, `SliderField` "Rent paid for": min 1, `sliderMax`/`max` set to term months, `integer`, `valueText={formatMonthCount}` and `hint={formatMonthCount(value)}`.

It goes in `PeopleControls` between the deposit split and the payment split. Unticking only sets `lodgerEnabled: false`, so the values are kept.
